Solution Orchestration

Orchestration connects Solution Models to Solution Factories — coordinating the sequence and parallelism of all factory activities through Workflows and Tasks.

Workflow Types
Build Workflow Hermetic build pipeline for a Solution
Test Workflow Test suite against a Solution build
Release Workflow build → test → stage → approve → deploy
Deployment Workflow Artifact to target environment
Rollback Workflow Restore prior Solution version
Provisioning Workflow Create and configure a new SDE
Governance Workflow Review, approve, CM promotion gates
Data Pipeline Workflow ETL operations for Solution data
Task Schema
task_id uuid — unique identifier
name string — human-readable label
workflow_ref ref — parent workflow
type build | test | deploy | review | approve | notify | script | manual
inputs data, artifacts, or conditions required to begin
outputs artifacts, state changes, or signals on completion
assignee user | team | service | ai_agent
status pending | running | succeeded | failed | skipped | blocked
dependencies task_id[] — must complete before this task
timeout duration — max execution before auto-fail
retry_policy { max_retries, backoff_strategy }

Governance Instruments

Governance ensures all Solutions, Factories, and Environments operate within defined quality, security, and compliance boundaries. It is enforced through seven distinct instruments.

◈
Policy
Declarative rules constraining behavior at the platform, factory, or solution level. For example: "All CM solutions must have passing security scans."
⊞
Standard
A defined approach or specification that Solutions must conform to — API versioning standards, naming conventions, data type usage.
⬡
Template
Pre-approved scaffolds for common Solution types, SDE configurations, or workflow definitions. Accelerate consistent creation.
▸
Playbook
Step-by-step guides for executing defined processes — Release Playbook, Incident Response Playbook, Vendor Qualification Playbook.
◎
Gate Criteria
The specific conditions that must be satisfied for a Solution to advance from one maturity stage to the next. Enforced automatically at promotion.
⊡
Audit Log
Immutable, tamper-evident record of all actions taken on Solutions, SDEs, and Factories. Append-only. Required for CM-stage compliance.

Ownership System

Every Solution on qala has an unambiguous owner. Ownership defines accountability for quality, security, and lifecycle decisions at every level of the hierarchy.

Governance Board
Approves CM-stage promotions and major lifecycle changes. Final authority.
Factory Owner
Responsible for operating a Solution Factory and its full SDE network.
Solution Owner
Individual or team accountable for the Solution's quality and roadmap.
Component Owner
Individual or team accountable for a specific Solution Component.
Maturity Gate Requirements
SANDBOX → DEV
Registry created · SDE provisioned · owner assigned
DEV → NIGHTLY
CI pipeline configured · build succeeds · basic tests passing
NIGHTLY → TEST
All unit + integration tests passing · SAST clean · no P1 defects
TEST → CM
All suites passing · DAST clean · benchmarks met · board sign-off · attestation generated

Security & Compliance

Security is embedded in the Solution lifecycle at every stage — not a separate concern. Enforced by the Security and Event Management (SEM) service.

RBAC
Role-Based Access
Enforced at every API endpoint and SDE operation. Roles resolve per user identity at the gateway.
mTLS
Mutual TLS
All service-to-service communication within the platform uses mutual TLS. No unencrypted inter-service traffic.
SAST
Static Analysis
Static Application Security Testing runs on every commit. Must be clean before DEV → NIGHTLY promotion.
DAST
Dynamic Analysis
Dynamic Application Security Testing against every build targeting TEST+ maturity. Required for CM promotion.
SLSA
Build Attestation
SLSA provenance records signed for every build output. Verified by the Gateway before any deployment proceeds.
SEM
Threat Detection
Real-time monitoring for anomalous activity, policy violations, and attack patterns. SDE quarantine on detection.
KMS
Secrets Vault
HashiCorp Vault or cloud-native KMS for all credentials, certificates, and secrets. No plaintext secrets in configs.
AUDIT
Immutable Audit Logs
All platform actions recorded in tamper-evident, append-only logs. Required for compliance reporting.
ENC
Data Encryption
Encryption at rest and in transit mandatory for all Solution and tenant data across the platform.
