Platform Object Hierarchy

Every deliverable.
One model.

qala treats every output — software, physical goods, services, platforms — as a Solution with a consistent structure, governed lifecycle, and traceable value chain.

The platform is itself a solution factory — the root factory — capable of producing tiered, hierarchical child factories, development environments, and solution models at any scale.

"Every solution, regardless of type or scale, is created, maintained, and operated within a standardized, reproducible, and governed environment."

01 Application Software with defined processes and user interactions
02 System Composed applications with coordinated behavior
03 Good Tangible or digital deliverables from a defined process
04 Product Market-facing offerings combining software, services, and goods
05 Service Capabilities delivered on-demand or continuously
06 Platform Substrate on which other Solutions are built and operated

The Maturity Model

Every Solution progresses through five governed stages. Promotion requires passing defined gate criteria.

SANDBOX
Sandbox
Exploratory, unconstrained. No stability guarantees. Open creation.
GateNone required — free creation
DEV
Development
Active feature development. Nightly builds may break. CI in progress.
GateSDE provisioned · owner assigned
NIGHTLY
Nightly
Automated nightly build and test cycle. Stability improving.
GateCI green · basic tests passing
TEST
Test
Feature-complete. Full test suites running. Pre-release hardening.
GateAll tests pass · SAST clean
CM
Control Managed
Release-qualified. Under Configuration Management control. Immutable.
GateDAST clean · board sign-off · attestation

Solution API
// Create a new Solution
POST /solutions
{
  "name":    "payments-platform",
  "type":    "platform",
  "version": "1.0.0",
  "maturity": "SANDBOX",
  "owner":   "team-payments",
  "tags":    ["fintech", "core"]
}

// Add a component to the Solution
POST /solutions/{id}/components
{
  "name": "auth-module",
  "type": "module",
  "design": "blueprint://auth-v2"
}

// Promote Solution maturity
POST /solutions/{id}/maturity
{
  "target": "DEV",
  "justification": "CI passing"
}

// Create an SDE in a Factory
POST /factories/{id}/sdes
{
  "template": "go-microservice-v3",
  "solution_ref": "sol_payments"
}

// Snapshot an SDE
POST /sdes/{id}/snapshot
// → { "snapshot_id": "snap_44f3a...", "version": 12 }
