Factory & SDE

The Solution Development Environment (SDE) is the atomic operational unit. SDEs are solution-agnostic: they define the conditions for creating, maintaining, and operating solutions, not the solutions themselves.

The SDE

One SDE can support a collection of Solutions. SDEs are deployable, configurable, distributable, version-controlled, composable, releasable, and scalable.

Sandbox
Open exploration and experimentation. No stability guarantees. Ephemeral by default.
Build & Assembly
Hermetic build and assembly. Isolated, reproducible, attested outputs.
Test
Full verification and validation. Auto-provisioned clones of production topology.
Release
Pre-release staging and CM sign-off. Immutable after CM gate.

Hermetic Build Environments

Builds are isolated, deterministic, and reproducible. Every artifact is fully traceable to its source, dependency graph, and execution environment.

IsolatedImmutable build containers
ReproducibleDeterministic dependency graphs
AttestedSigned provenance records
SLSA Provenance
Each build emits signed provenance with source, dependencies, environment, and output hashes. Policy enforcement ensures only verified artifacts progress to Release and CM stages.
Solution Tooling

Tooling is organized as Tools, Toolsets, Toolkits, Toolchains, and governed Tool Suites. Each layer builds on the previous to standardize solution delivery.

Toolset
Curated set of tools for a specific task or workflow.
Toolkit
Collection of toolsets covering a full domain of practice.
Toolchain
Ordered sequence of tools with version-controlled outputs.
SDE Lifecycle States

An SDE transitions through seven lifecycle states. The state determines allowed operations and resources.

Provisioning
Environment assembled from template or definition.
Active
Fully operational; all development and build activities occur here.
Snapshotted
State captured while environment continues to run normally.
Suspended
Resources released; state preserved for resumption.
Rolled Back
Restored to a prior snapshot; CI/CD resumes.
Archived
Long-term storage with reactivation on demand.
Terminated
Decommissioned with backups retained per policy.
